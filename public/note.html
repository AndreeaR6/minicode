Datele din pagina se pierd

Ce scrii intr-o pagina web sta in memoria paginii. Inchizi pagina si dispare.

Ca la scoalaScrii pe ciorna si arunci foaia. Ca sa pastrezi ceva, il copiezi pe curat.

Salvat inseamna scris in afara paginii. Sunt trei variante:

  • localStorage: in browser, doar pe calculatorul si browserul pe care l-ai folosit.
  • fisier: de exemplu un JSON, pe care il duci unde vrei.
  • server cu baza de date: PHP si SQL.

localStorage tine doar siruri de text si ramane si dupa ce inchizi browserul. Intr-o fereastra privata se comporta ca sessionStorage, adica se sterge la inchidere.

localStorage.setItem("cv", JSON.stringify({ name: "Maria" }));
const saved = JSON.parse(localStorage.getItem("cv"));
console.log(saved.name);

JSON

  
JSON e text care descrie date. Poate avea obiecte {}, liste [], texte, numere, true, false si null.

  
Regulile: cheile sunt in ghilimele duble, nu are virgula la sfarsit, nu are comentarii si nu are undefined.

  
Ca la scoalaO fisa de elev completata: aceleasi campuri, scrise la fel pentru oricine o citeste.

  
    
    
  1. Obiectul din cod devine text cu JSON.stringify.
    2. 
    
  2. Textul devine obiect la loc cu JSON.parse.
    3. 
    
  3. Daca textul e stricat, JSON.parse da SyntaxError.
    4. 
  

  


const cv = { name: "Maria", skills: ["PHP", "OOP"], years: 3 };
const text = JSON.stringify(cv, null, 2);
console.log(text);
const back = JSON.parse(text);
console.log(back.skills[1]);

Salvare si incarcare

  
    
    
  1. Editezi in formular.
    2. 
    
  2. 'Salveaza ca JSON' scrie datele ca text: mai intai format si version, apoi sectiunile.
    3. 
    
  3. Pastrezi fisierul.
    4. 
    
  4. 'Incarca JSON' citeste textul cu JSON.parse.
    5. 
    
  5. Editorul verifica format si version. Daca nu se potrivesc, refuza si lasa datele cum erau.
    6. 
    
  6. Pune datele in formular si refaci previzualizarea.
    7. 
  

  
Cand schimbi structura fisierului, urci version. Un fisier vechi se recunoaste dupa numar.

  


function load(text) {
  const o = JSON.parse(text);
  if (o.format !== "cv-editor") throw new Error("Nu e un JSON de CV");
  if (o.version !== 1) throw new Error("Versiune necunoscuta: " + o.version);
  return o;
}

Fara server

  
Editorul ruleaza doar in browser. JavaScript citeste si scrie datele, deci nu e nevoie de PHP si SQL.

  
Serverul cu baza de date merita cand mai multi oameni scriu aceleasi date sau cand datele trebuie sa fie la indemana pe alt calculator. Pentru un editor personal e prea mult.






  
OOP

  
OOP inseamna programare orientata pe obiecte: datele stau impreuna cu codul care le modifica, in obiecte.

  
Ca la scoalaClasa e formularul gol. Obiectul e formularul completat de un elev.

  
    
    
  • clasa: schita dupa care faci obiecte.
    • 
    
  • obiect: un exemplar facut dupa schita, cu datele lui.
    • 
    
  • incapsulare: datele si metodele care le schimba stau in acelasi loc.
    • 
    
  • mostenire: o clasa preia ce are alta clasa.
    • 
    
  • polimorfism: aceeasi metoda se comporta diferit, dupa tipul obiectului.
    • 
    
  • abstractizare: scoti la vedere doar ce trebuie folosit.
    • 
  

  


class Cv {
  constructor(name) { this.name = name; this.skills = []; }
  addSkill(s) { this.skills.push(s); return this; }
  toJSON() { return { name: this.name, skills: this.skills }; }
}
const cv = new Cv("Maria").addSkill("PHP").addSkill("OOP");
console.log(JSON.stringify(cv));

Acelasi lucru in PHP 8 (de rulat pe server sau cu php in terminal):

  


<?php
class Cv {
    private array $skills = [];

    public function __construct(private string $name) {}

    public function addSkill(string $s): static {
        $this->skills[] = $s;
        return $this;
    }
}

$cv = (new Cv("Maria"))->addSkill("PHP")->addSkill("OOP");

Git

  
Git tine istoricul fisierelor unui proiect. Fiecare commit e o poza a intregului proiect la un moment dat.

  
Ca la scoalaUn caiet cu data pe fiecare pagina. Nu stergi nimic, adaugi pagini noi si te poti intoarce la oricare.

  
Un fisier poate fi in trei stari: modificat, pregatit pentru commit (staged) si salvat in commit. Aproape totul se face pe calculatorul tau, fara internet, pana la push.

  


git clone <adresa-repo>
git add index.html README.md
git commit -m "Add CV editor"
git push origin main

    
terminal

  

  
    
    
  • clone descarca repo-ul si il leaga de origin.
    • 
    
  • add pune fisierele in staging.
    • 
    
  • commit salveaza local, cu un mesaj scurt.
    • 
    
  • push trimite commit-urile pe GitHub, daca ai drept de scriere si nimeni n-a trimis intre timp.
    • 
  

  
CV-ul tau real si parolele nu intra in repo.

Verifica-te

  
Ce se intampla cu datele din pagina cand o inchizi?
Se pierd, daca nu le-ai salvat in afara paginii.

  
Ce face JSON.parse pe un text stricat?
Da SyntaxError.

  
Ce rezulta din JSON.stringify({ a: undefined, b: () => 1 })?
{}. Ambele proprietati sunt sarite.

  
De ce are fisierul 'format' si 'version'?
Ca editorul sa refuze un fisier strain sau de alta versiune, fara sa strice datele din formular.

  
Care e diferenta dintre clasa si obiect?
Clasa e schita. Obiectul e un exemplar facut dupa ea, cu datele lui.

  
Ce face git push?
Trimite commit-urile locale pe remote, de exemplu pe GitHub.
